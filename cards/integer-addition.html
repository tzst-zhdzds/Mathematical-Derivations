Integer Addition and Subtraction

Adding Two Walks

Suppose the first walk has record (a, b) and the second has record (c, d). Walk them one after the other. Altogether we take a + c forward steps and b + d backward steps. This suggests the following rule for adding their classes:

[(a, b)] + [(c, d)] = [(a + c, b + d)].

Inside the pair, we add natural numbers. The plus sign between the two classes is the integer addition we want to define. A record whose class is a given integer is called a representative of that integer.

What If We Use Another Representative?

Start with one forward step, recorded as (1, 0), and add the integer -1. On the previous card we found two records for -1: (0, 1) and (1, 2). Try each one in the proposed rule.

[(1, 0)] + [(0, 1)] = [(1, 1)].

[(1, 0)] + [(1, 2)] = [(2, 2)].

Do these answers agree? The equivalence test for (1, 1) and (2, 2) asks whether 1 + 2 = 2 + 1. This holds by Theorem 16. By Theorem 26, [(1, 1)] = [(2, 2)]. We need this to work for every pair of integers, even when we change both representatives.

Theorem 27: Integer Addition Is Well-Defined

For every pair of integers, the rule above gives exactly one integer as their sum. In particular, every choice of representatives gives the same output class.

Proof. Choose a representative (a, b) of the first integer and (c, d) of the second. Such records exist by the definition of an integer. By Theorem 13, a + c and b + d are natural numbers. Their pair therefore has a class in ℤ. This gives us an output.

Now choose other representatives (a', b') and (c', d') for the same two integers. The primes mark the new entries. By Theorem 26, each old record is equivalent to its replacement. Writing out the two equivalence tests gives

a + b' = a' + b and c + d' = c' + d.

Our output records are (a + c, b + d) and (a' + c', b' + d'). Apply the equivalence test to these two records. The first entry of each record must be added to the second entry of the other. Thus our goal is

(a + c) + (b' + d') = (a' + c') + (b + d).

Start on the left. By Theorem 17, we can regroup the sum to bring c and b' together. By Theorem 16, we can swap them. Regrouping gives

(a + c) + (b' + d') = (a + b') + (c + d').

Now each parenthesis matches one of our two input equalities. Replace a + b' with a' + b, and c + d' with c' + d. We get

(a + b') + (c + d') = (a' + b) + (c' + d).

Use the same two addition laws to swap the middle terms b and c' and regroup. This reaches our goal:

(a' + b) + (c' + d) = (a' + c') + (b + d).

The output records pass the equivalence test, so their classes are equal by Theorem 26. We have proved that every pair of integers gives exactly one output integer. By Theorem 11, this rule defines a function from ℤ × ℤ to ℤ. This function is addition on the integers.

Zero in the Integers

A walk with no steps has record (0, 0). We call its class the integer zero and write 0ℤ = [(0, 0)]. How can we recognize other records in this class? By Theorem 26, the class of (u, v) equals [(0, 0)] exactly when u + 0 = 0 + v. By Theorem 13 and Theorem 14, this reduces to u = v.

[(u, v)] = 0ℤ ⇔ u = v.

Adding integer zero leaves every integer unchanged. Indeed, if x = [(a, b)], then Theorem 27 gives both calculations:

x + 0ℤ = [(a + 0, b + 0)] = [(a, b)] = x.

0ℤ + x = [(0 + a, 0 + b)] = [(a, b)] = x.

Theorem 28: Every Integer Has a Unique Additive Inverse

An additive inverse of x is an integer y such that both x + y and y + x equal integer zero. We will show that every integer x has exactly one additive inverse. We write it as -x.

Suppose x = [(a, b)]. To undo the walk, switch forward and backward steps. This suggests using [(b, a)] as the inverse. First check that switching entries gives the same class for every representative of x.

Suppose [(a, b)] = [(c, d)]. By Theorem 26, a + d = c + b. Read this equality in reverse and use Theorem 16 to exchange the two addends on each side:

b + c = c + b = a + d = d + a.

The equality b + c = d + a is the equivalence test for (b, a) and (d, c). Thus [(b, a)] = [(d, c)].

Now take y = [(b, a)]. Adding in the two possible orders gives

x + y = [(a + b, b + a)].

y + x = [(b + a, a + b)].

Since a + b = b + a, each output record has equal entries. By our test for integer zero, both sums equal 0ℤ. Thus y is an additive inverse of x.

Could another integer work? Suppose z = [(c, d)] is also an additive inverse of x. Then x + z = [(a + c, b + d)] equals integer zero, so a + c = b + d. Exchanging the addends on the left gives c + a = b + d. This is exactly the test for (c, d) ∼ (b, a). Therefore z = [(b, a)] = y. The inverse is unique, and we have proved the formula

-[(a, b)] = [(b, a)].

Integer Subtraction

For integers x and y, we define x - y to mean x + (-y). In -y, the minus sign takes the additive inverse of one integer. In x - y, it denotes subtraction of the second integer from the first.

To compute with records, first use Theorem 28 to switch the entries of the second record. Then use Theorem 27 to add:

[(a, b)] - [(c, d)] = [(a, b)] + [(d, c)] = [(a + d, b + c)].

Each step gives a unique integer for the given inputs, so the result is independent of the representatives used in the calculation.

For example, subtract the class of two forward steps from the class of one forward step:

[(1, 0)] - [(2, 0)] = [(1, 0)] + [(0, 2)] = [(1, 2)].

Is this the integer we named -1? The test for (1, 2) ∼ (0, 1) asks whether 1 + 1 = 0 + 2. Both sides equal 2. Hence [(1, 2)] = [(0, 1)] = -1.
